# Bridge 0.3.85 回调路由候选

本地日期：2026-09-10。自动化执行：Codex；真实双端交互复核待用户重启后完成。

## 范围与实现

基线为 76a3c2d 及尚未提交的 0.3.80-0.3.84 修改。本次触发 Controller/Shim、桌面
启动入口、app-server 生命周期、跨客户端路由及依赖回归，不修改 Executor 协议。

- 新入口按 CODEX_HOME 隔离，优先使用已有受管服务。通过原生 loaded-thread 索引把
  已有 thread 请求送回实际执行实例，不为了统一 PID 中断任务。无实例才创建用户级
  服务，用内核 lifetime lock 仲裁冷启动。过渡期允许多个后台分别执行不同线程。
- 受管旧 journal 中，只有 owner 已退出、native PID/启动时间/执行身份与配置域均可
  验证，且有私有认证入口的实例才进入路由。未受管桌面 stdio 后台不会被接管或终止。
- 请求采用唯一 wire ID 和 Promise 回调表；同线程有序请求等待 ACK，而非等待整轮
  执行。turn/steer 与 turn/interrupt 不进入普通请求队列。原生 thread/queue 接口
  保持原响应，不把 queued submission 伪造成已启动 turn。
- 响应回给请求者，线程事件转发，审批首次回答生效。客户端断开不发送自动 interrupt；
  超时/断线以 unknown outcome 报错，不重放写操作。回调、连接与缓冲均设上限。
- 桌面全项目列表不加单根过滤，VS Code 列表仍按当前工作区过滤。桌面注入的 MCP
  TOML 配置经过 smol-toml 解析，随 thread/start、resume、fork 的 config 传入，
  不丢弃桌面工具配置，也不改写共享全局配置文件。
- 新增 ChatGPT (Shared Codex) 独立入口与可卸载启动器。使用官方安装包已存在的
  CODEX_CLI_PATH 路径选择，不修改 app.asar 或官方可执行文件，不覆盖原 ChatGPT
  入口，不自动重启用户应用。content-addressed Shim 校验后复用，入口更新有恢复记录。

已核对[官方线程协议](https://learn.chatgpt.com/docs/app-server#threads)及安装包实际
启动实现。官方原生 daemon 入口存在，但桌面含运行期 MCP 覆盖配置，不能只设置一个
daemon 开关。此候选选择共享请求入口与旧实例路由，不宣称已全面切换原生 daemon。

## 首次接入

1. 安装候选与桌面入口后，不立即杀旧桌面进程；先让旧桌面任务完成。
2. 用户手动退出旧桌面端，从 ChatGPT (Shared Codex) 或 chatgpt-codex-bridge 启动。
   旧应用仍运行时再次点击入口只会激活旧进程，不能改变其后台。
3. 用户重载 VS Code，读取 client.shared_attached/client.callback_route 审计，核对
   原 thread 所指 native PID，测试两项目、追加/停止/队列/审批及长对话。

结论：已实现 Linux 统一回调入口候选；真实桌面 UI 未验收、灰屏未宣称修复。
现有活跃后台未被终止。按项目集成门禁，代码仍待真实 UI/Remote SSH 验收后提交。
