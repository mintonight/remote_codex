   与当前 `product.json` 的 Workbench checksum 匹配。这是未安装接收补丁的当前资产，
   不是已加载受管补丁的证据。受管状态目录没有 Workbench 备份或元数据，仅余锁文件。
2. `~/.vscode/extensions/openai.chatgpt-26.5901.22334-linux-x64/webview/assets/`
   下的 `app-initial-2e80ba27d368.js` 仍含引用补丁；当前文件与备份分别匹配元数据中的
   patched/original SHA-256。两端补丁状态不完整，足以解释接收链路无法工作。
3. `~/.config/Code/logs/20260908T011339/window1/exthost/`
   `zkbot.codex-vscode-remote-bridge/Codex Remote Bridge.log:5` 记录
   `Timed out waiting for the Workbench drop compatibility lock`。
   读取时锁中 PID 对应进程已不存在。该观测证明遗留锁存在，不证明超时发生时进程已死亡。
   实现仅在锁超过 30 秒后回收，但单次等待约 5 秒；异常退出后的下一次激活可能先超时。
4. 同日志中的 `layout.integration result=unavailable` 只表示视图位置修复命令集不可用；
   `src/extension/view-location.ts` 不检查拖放补丁，不应把该状态作为拖放兼容性结论。
5. 升级前的 `20260906T161336/window10` Bridge 日志同时存在文件拖放完成记录和
   `Unsupported dropped resource scheme: data`。失败样本仅解析到一个 `data:` URI，
   不能称为真实本地文件路径，也不能据此认定升级后所有路径解析失效。未复制 URI 内容。
