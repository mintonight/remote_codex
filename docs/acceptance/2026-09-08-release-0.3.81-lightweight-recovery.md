# Bridge 0.3.81 轻量后台恢复候选

日期：2026-09-08，America/Adak。执行人：Codex；真实 UI 验收待用户操作。

## 目标与触发项

用户明确要求预防反复灰屏，而不是依赖重载恢复。已知 renderer 于 18:19:36 原生崩溃，
但缺少匹配符号，尚不能确定原生触发函数。此次只修正源码中可直接确认的负载放大：
`0.3.80` 会每 30 秒读取活动线程完整历史，并合成 `thread/started` 向前台全量重放。
这可能放大长对话处理开销，不应被当作正常的健康检查。

命中 Controller/Shim、会话恢复和生命周期回归；根包及锁文件升至 `0.3.81`，Executor
`0.2.21` 和远端协议不变。此前未提交的 `0.3.80` 集成实现仍保留，不改写旧验收记录。

## 行为变化

- 去除自动恢复中的全部完整历史读取及合成 `thread/started` 快照。
- 后台订阅使用 `thread/resume` 的 `excludeTurns=true`；不重复恢复当前前台线程。
- 元数据读取固定 `includeTurns=false`，只转发合法且有变化的轻量运行状态。
- 原生增量消息照常转发；官方 UI 自己发起的历史查询不被截断或篡改。
- 已由原生事件发布的状态不再重复发送；完成态和后台空闲订阅回收保留。
- 退休线程的状态缓存清除，异常状态字段不进入前台。周期审计只包含数量与耗时，
  不包含会话正文、历史 turns、凭据或请求内容。

这不是静音 ResizeObserver 日志、禁用 GPU 或自动重载页面，也不承诺已经根治原生崩溃。
后台进程保活仍仅启用在 Linux 本地窗口；Remote SSH/Windows 边界不变。
